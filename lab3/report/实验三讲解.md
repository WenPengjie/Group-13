# 实验三讲解：CPU 怎样处理突发事件后继续原来的工作

小组：祝安毅 2511057、洪亮 2511955、闻鹏杰 2511565。

## 1. 这次实验究竟解决什么问题

实验一让内核能够启动、打印；实验二让内核知道哪些物理页可以分配。实验三让内核可以处理运行中的突发事件，并在处理后继续执行。

例如，内核正在执行一段计算，定时器到了预定时刻，CPU先转去处理时钟中断；处理结束以后，计算的寄存器和位置必须与被打断时一致。否则，程序可能算出错误结果、跳到错误地址，甚至破坏栈。

实验目的中的三个重点分别对应三件事：理解RISC-V的Trap寄存器；把寄存器正确保存和恢复；用断点与时钟中断证明整个流程确实能返回。

## 2. 先分清中断、异常和Trap

| 概念 | 如何触发 | 本次例子 | 返回位置 |
|---|---|---|---|
| 中断 interrupt | 外部事件异步到来，与当前具体指令没有直接因果关系 | S态时钟中断 | 保留硬件记录的epc，不能随便加4 |
| 异常 exception | 当前指令执行引起的同步事件 | 非法指令、断点 | 本次处理后跳过相应2/4字节指令 |
| Trap | 上述两类进入处理机制的总称 | 两者都进入 `__alltraps` | 由处理程序与`sret`共同决定 |

指导书有时用“断点中断”作宽泛称呼；严格按RISC-V分类，断点是同步异常。

## 3. 一次Trap从头到尾怎么走

```text
原程序运行
  ↓ 硬件记录 sepc / scause / stval / sstatus，并转入 stvec
__alltraps
  ↓ SAVE_ALL：把原寄存器保存在内核栈，形成288字节TrapFrame
  ↓ a0 = sp；调用 trap(a0)
trap → trap_dispatch
  ├─ scause最高位为1 → interrupt_handler
  └─ scause最高位为0 → exception_handler
  ↓ C处理返回，sp仍指向同一个TrapFrame
__trapret
  ↓ RESTORE_ALL：恢复CSR、通用寄存器，最后恢复原sp
  ↓ sret：根据sepc/SPP/SPIE恢复执行位置、特权级和中断状态
原程序继续
```

硬件不会替你把x1到x31自动压栈；这些是 `SAVE_ALL` 的工作。硬件也不会因为执行了 `sret` 就替你从栈中装回通用寄存器；这是 `RESTORE_ALL` 的工作。

## 4. 为什么有288字节？为什么sp必须最后恢复？

RV64中每个寄存器槽位8字节。32个通用寄存器槽位，再加4个CSR快照，因此 `36×8=288`。288是16的整数倍，符合C函数调用时的栈对齐要求。

| 槽位 | 字节偏移 | 内容 |
|---|---:|---|
| 0..31 | 0..248 | x0..x31，其中槽位2是Trap前的sp |
| 32 | 256 | sstatus |
| 33 | 264 | sepc |
| 34 | 272 | stval（旧头文件称sbadaddr） |
| 35 | 280 | scause |

假设Trap前 `sp=S`，保存后 `sp=S-288`。恢复期间所有 `LOAD ... (sp)` 都需要以 `S-288` 为基址。如果先恢复sp为S，后面的加载就读错位置。所以最后才执行：

```asm
LOAD x2, 2*REGBYTES(sp)
```

这条指令右侧仍用旧sp访问帧，读取成功后才把结果写入x2。槽位2保存的是Trap前的sp，不是中断帧指针。x0固定为0，不需要恢复。

## 5. 汇编为什么用a0传参？

C函数签名是 `void trap(struct trapframe *tf)`。RISC-V ABI约定第一个参数放在a0，当前sp恰好指向TrapFrame，于是使用：

```asm
mv a0, sp
jal trap
```

原a0、ra已经保存到帧，所以临时改变它们没有关系。C函数遵守ABI，返回时sp保持调用前的值；随后还可以按同一个帧恢复原上下文。

## 6. 几个CSR分别干什么

| CSR | 用途 | 本次怎样使用 |
|---|---|---|
| stvec | Trap入口地址和模式 | Direct模式指向四字节对齐的`__alltraps` |
| sepc | 发生Trap时的执行位置 | 异常处理可能更新；返回时恢复到硬件sepc |
| scause | 原因码 | 最高位区分中断/异常，其余位区分类型 |
| stval | 故障辅助信息 | 随帧打印，帮助诊断 |
| sstatus | 保存特权级和中断状态 | SPP决定返回S/U态，SPIE决定返回后的SIE |
| sie | 各来源的中断开关 | `clock_init`打开STIE |
| sscratch | 入口临时保存工具 | 先暂存原sp，保存后清0 |

`sret`不是“必定回用户态”。本实验从内核S态触发Trap，保存的SPP为1，因此返回S态。后续如果要支持用户态，需要补上内核栈切换等机制，不能只把SPP强行清0。

## 7. 为什么时钟必须每次重新设置

`sbi_set_timer`设置的是一个未来时刻，不能理解为“自动每10ms循环”。第一次事件由 `clock_init` 设置，之后每次进入S态时钟处理分支，都需要再次安排下一次事件。

```c
clock_set_next_event();
size_t current_ticks = ticks + 1;
ticks = current_ticks;
if (current_ticks % TICK_NUM == 0) {
    print_ticks();
    if (++reports >= SHUTDOWN_AFTER) {
        sbi_shutdown();
    }
}
```

QEMU的time计数频率为10MHz，源码设置间隔100000个time单位，所以约10ms一次中断，100次约1秒。这里是计时器频率，不能直接把它当成任意CPU的指令执行频率。

`ticks`是总中断次数，`reports`是打印次数。第200次中断时，`ticks=200`，但每行仍按课程格式打印 `100 ticks`；不能因为出现两行100就误以为计数器每次清零。

最终版本把这个常见分支放在其他诊断分支之前，避免时钟处理经过switch跳转表；局部变量还避免为了取模重复读取volatile的ticks。每100次才打印一次。反汇编和回归记录支持这些局部改进，但没有真实硬件基准来证明某个提速倍数。

网页提到 `SHUTDOWN_AFTER`，本地却没有定义，也没写具体数字。本实现显式补充默认10，因此正常运行1000次中断后关机。该值可配置，报告没有把10声称为网页给定值。

## 8. 为什么异常返回地址有时加2，有时加4

`c.ebreak`是16位压缩指令，占2字节；普通`ebreak`是32位，占4字节。首半字最低两位不是二进制11时，是16位编码；本实验普通32位编码最低两位为11。

```c
tf->epc += ((*(const volatile uint16_t *)tf->epc & 3) == 3) ? 4 : 2;
```

如果永远不移动epc，就会返回同一条异常指令，反复进入Trap；如果对2字节断点统一加4，就会跳过后面本来应该执行的2字节内容。读取首半字也避免了把仅2字节对齐的32位指令当作4字节对齐数据读取。

这段代码适用于本次已映射、可读的内核指令，覆盖16/32位情形。它没有处理用户地址不可读、跨页安全取指或未来48位及以上编码，这些不是本实验已实现的能力。

## 9. 关闭中断和内存分配有什么关系

空闲页链表更新可能需要多步。如果本核在链表只改了一半时被中断处理程序再次访问分配器，就可能看到不一致的数据。因此Lab3在分配、释放、查询空闲页时保存SIE并临时关闭本核中断。

关键是“恢复原状态”：调用前关着，就必须保持关闭；调用前开着，完成后才重新开启。不能无条件 `intr_enable()`。这样内外两层临界区嵌套时，内层不会提前打开中断。

宏中的 `do { ... } while (0)` 让宏展开后在语法上像一条完整语句，方便放在 `if/else` 中，并要求调用处正常加分号。这不是运行时循环，也不是提供原子性的来源。

本核关中断只避免本核中断重入，不能阻止另一个CPU同时访问链表。多核仍需自旋锁等互斥机制。

## 10. 实际测试说明了什么

- 原始评分：上下文/断点35分，非法指令及兜底25分，持续时钟40分，合计100/100。
- 正常启动：连续十行 `100 ticks`，`make qemu`返回0，验证默认阈值下的SBI关机。
- 扩展运行：明确编码的16/32位异常都返回；全部可写GPR、sp、ra、gp、tp保持；关闭和开启两种SIE状态都正确恢复；混合异常后还能累计到250次时钟中断。
- 迁入的Best-Fit在扩展副本中通过了课程原始自检；提交源码默认仍使用框架的First-Fit。

真实日志结果图和完整日志位于 `images/`、`logs/`；结果图为日志排版图，原生窗口截图未取得，二者已在报告中区分。这些结果没有证明用户态隔离、多核安全、所有设备中断或所有异常都已完成。

“本实验让内核具备处理Trap后返回原执行流的能力。硬件先保存原因、返回位置和部分状态，再跳到stvec。汇编入口把通用寄存器和CSR快照保存成288字节的TrapFrame，把帧地址放入a0调用C函数。C函数根据scause区分中断与异常：时钟中断要续设下一次事件并计数；断点和非法指令要根据2/4字节长度移动epc。最后汇编恢复CSR和寄存器，sp最后恢复，再由sret恢复执行位置和中断状态。官方评分与额外边界测试说明这个闭环能正确运行。”
